  Name: The documentation shows the data is TinyEHR v0.2.0, a 100-patient
  derivative of the MIMIC-IV Demo v2.2. I named the skill tinyehr-context rather
  than mimic-iv-context because the data has three changes from MIMIC. Dates
  are shifted again, ICD codes carry decimals, and the clinical notes are
  LLM-generated. Tell me if you would prefer the MIMIC name.

  Sources:
  - Converted: all 58 documentation files, with none failed or skipped. That
    includes the PDF paper, whose extracted tables I did not check against the
    PDF layout.
  - Listed only: 34 data files, by name and size. None were opened.
  - Placeholder tags: I did not copy the patient-style example rows from the
    TinyEHR README, so nothing patient-level is in the output.

  Pedigree questions: All six are answered from the documents. These items
  remain open in section 8:
  - Patient selection: how the 100 demo patients were chosen is not documented.
  - Date shifting: it is unclear whether anchor_year and several other date
    fields were also shifted. The About document lists only dod as changed for
    patients, but the README shows realistic anchor years.
  - Conflicting statements:
    - eMAR rollout is given as 2011–2013 in the table page and 2014–2016 in the
      paper.
    - Ages over 89 are capped at 91 in one place and 300 in another.
  - Key and value gaps: primary keys for several event tables and value lists
    for several categorical fields are undocumented.
  - Generated notes: whether they match the structured data is unmeasured.
  - Literature: PubMed turned up no validation or data-quality papers for
    TinyEHR or MIMIC-IV. The only relevant hit is a 2026 teaching paper on the
    MIMIC-IV Demo, which I recorded in section 7.

  Rules seeded: 72 rule entries across 18 tables. They are hypotheses, and rules
  that rest on inference or conflicting documents are labelled as such in their
  source field. Some are expected to fail legitimately, for example
  negative-length admissions from organ-donor accounts.
